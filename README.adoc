= Neovim Configuration

An AstroNvim v6 based configuration for Windows, tuned for this machine: snacks.nvim as the
picker/UI backbone, blink.cmp for completion, flash.nvim for jumping, and treesitter parsers
compiled with zig because there is no MSVC here.

toc::[]

== The stack, in one table

|===
|Layer |What is used |Why

|Distribution
|AstroNvim v6 (`version = "^6"`)
|Base framework: astrocore/astrolsp/astroui, mason, LSP setup, heirline statusline.

|Completion
|blink.cmp v1.0
|Insert + cmdline completion, snippet navigation. Owns `<Tab>`.

|Pickers & UI
|snacks.nvim
|File/grep/pickers, dashboard, explorer, notifications, zen, dim, indent guides, terminal, scratch buffers, lazygit.

|Jumping
|flash.nvim
|`s` jump, labelled `f`/`t`, treesitter selection. See xref:keybindings.adoc#_flash[Keybindings → Flash].

|Text objects
|mini.nvim (surround, ai, animate)
|`gs` surround prefix, treesitter-backed `a`/`i` text objects, cursor/resize animation.

|Formatting
|conform.nvim
|stylua, goimports, ruff/black, `lsp_format = "fallback"`, format-on-save.

|Search & replace
|grug-far.nvim
|Project-wide search/replace in a normal buffer. snacks greps, grug-far rewrites.

|File manager
|yazi.nvim + snacks explorer
|`<Space>-` opens yazi at the current file; `<Space>e` is the snacks explorer. Inside yazi,
`F` = flash-style jump to an entry by first character (official `jump-to-char.yazi`, bound in
`%APPDATA%\yazi\config\keymap.toml`). The yazi plugins (`git.yazi`, `jump-to-char.yazi`,
`ouch.yazi`) are built by `yazi.lua` into the real config dir — `yazi.nvim`'s default
`~/.config/yazi` is not read on Windows, and its symlink install needs Developer Mode.

|Git
|gitsigns, lazygit, diffview.nvim
|Inline hunks, `<Space>gg` lazygit, `<Space>gD`/`gF`/`gH` diff & history views.

|Completion extras
|copilot.vim
|Ghost text suggestions. Accept with `<M-CR>` — blink.cmp owns `<Tab>`.
|===

The full plugin inventory with file locations is in xref:#_plugin_map[Plugin map] below.

== Requirements

* **Windows** (developed and used on Windows 11; paths assume `%LOCALAPPDATA%`)
* **Neovim 0.12+** — installed at `C:\Users\Ahri\Software\Neovim` on this machine
* **zig** on `PATH` or at `C:\Users\Ahri\Software\Ziglang\zig.exe` — used to compile treesitter
  parsers (see below)
* **ripgrep** — snacks grep and grug-far
* **yazi** — the `<Space>-` file manager
* **Node.js** — copilot.vim
* **PowerShell (pwsh)** — `init.lua` wires `:sh`, `:!` and toggleterm through pwsh with UTF-8

browse everything live.

including the flash `s`/`S`/`gS` scheme, the blink chartoggle, all picker menus, LSP, DAP,

== Treesitter parsers without MSVC

This machine has no usable MSVC (Build Tools exist but the Windows SDK component is missing),
and nvim-treesitter `main` compiles parsers on demand expecting `cl.exe`. `treesitter-zig-cc.lua`
builds a tiny shim (`scripts/zig-cl.c`) into `%LOCALAPPDATA%\nvim-data\bin\zig-cl.exe` on first
use and points `CC` at it. Result: `:TSInstall` and `:TSUpdate` work normally.

[IMPORTANT]
====
After `:Lazy update` moves `nvim-treesitter`, run `:TSUpdate` — otherwise highlighting breaks
with `Query error ... Invalid field name`. Full post-update workflow:
xref:docs/maintenance.md[docs/maintenance.md].
====

== Updating

1. Run `:Lazy update` **twice** (first pass updates AstroNvim, second applies its snapshot).
2. If `lazy-lock.json` shows `nvim-treesitter` moved, run `:TSUpdate`.
3. New formatters/LSP servers arrive via Mason: `<Space>pm`, `<Space>pM`.

== Installation (fresh machine)

[source,shell]
----
git clone https://github.com/Marin-Kitagawa/astronvim.git "$env:LOCALAPPDATA\nvim"
----

Start `nvim`; lazy.nvim bootstraps itself, installs plugins from `lazy-lock.json`, and the
treesitter shim compiles parsers on first open of a new filetype. Prerequisites from
xref:#_requirements[Requirements] must be on `PATH` (or in `~\Software` for zig).
